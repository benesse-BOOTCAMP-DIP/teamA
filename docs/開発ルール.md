# A班: 開発ルール

このドキュメントは、A班における開発フロー、ブランチ運用、命名規則、プルリクエストおよびAI活用時のルールをまとめたものです。

---

## 🌿 1. ブランチの使い方

開発で使用するブランチは以下の **3種類** です。

| ブランチ名 | 役割 |
| :--- | :--- |
| `main` | 発表やデモで見せる本番環境。**常に動く状態**を保ちます。 |
| `develop` | 開発の本流。全員の開発成果をここに合流させます。 |
| `feature/...` | 各自の作業ブランチ。`develop` から切って、`develop` に戻します。 |

> ⚠️ **重要**: `main` と `develop` には直接 push しません。必ず作業ブランチを作って PR（Pull Request）を出します。

### 🔄 作業の流れ

1. **`develop` の最新を取得してからブランチを切る**
   ```bash
   git switch develop
   git pull
   git switch -c feature/word-register-api
   ```
   > ⚠️ 前の作業ブランチのまま次の作業を始めないでください。毎回必ず `develop` に戻って `pull` してから切り直します。

2. **作業してコミットする**

3. **push して PR を出す**
   ```bash
   git push -u origin feature/word-register-api
   ```
   GitHub 上で `develop` に向けて PR を作成します。

4. **レビューをもらってマージする**

5. **マージしたらブランチを消す**
   GitHub の PR 画面に出る「Delete branch」ボタンを押します。

6. **`main` へのマージ**
   スプリントが終わったタイミングで `develop` から `main` へ 1 回だけマージします。

## 🏷️ 2. ブランチ名・タスク一覧 (スプリント1)

ブランチ名は **小文字英数字ケバブケース**（`feature/機能名`）とします。

### 📌 カードとブランチの対応

#### バックエンド1
| カード | ブランチ名 |
| :--- | :--- |
| テーブル作成 | `feature/db-schema` |
| 単語登録API作成 | `feature/word-register-api` |
| 単語一覧取得API | `feature/word-list-api` |
| 単語削除API | `feature/word-delete-api` |

#### 単語登録画面 (`feature/register-page`)
| カード | ブランチ名 |
| :--- | :--- |
| 単語入力フォームと行追加ボタンの実装 | `feature/word-input-form` |
| 入力バリデーションと登録前の整形処理 | `feature/word-form-validation` |
| 登録ボタンの実装および物語生成処理の呼び出し | `feature/word-register-submit` |
| バックから返して欲しいデータ型を決めて伝える | ブランチ不要（相談タスク） |

> 💡 **注意**: 上記3本は同じファイルを変更するため、上から順番に 1 本ずつマージしてください（1 人が続けて担当するのが安全です）。

#### 単語・物語一覧画面 (`feature/lists-page`)
| カード | ブランチ名 |
| :--- | :--- |
| タブの実装 | `feature/list-tabs` |
| 単語タブの作成 | `feature/word-tab` |
| 物語タブの作成 | `feature/story-tab` |

> 💡 `feature/list-tabs` が入れ物となるため、先にマージします。


#### 物語詳細画面 (`feature/story-detail-page`)
| カード | ブランチ名 |
| :--- | :--- |
| 物語詳細ページの日本語訳コンポーネント作成と単語対照の表示 | `feature/japanese-translation` |
| キーワード入力欄および検索ボタンの実装 | `feature/search` |
| 「和訳を見る」アコーディオン展開 | `feature/japanese-translation-button` |

#### AI連携
| カード | ブランチ名 |
| :--- | :--- |
| LLM APIクライアントのセットアップ | `feature/llm-client` |
| システムプロンプトの設計 | `feature/story-prompt` |
| AI応答のパースとデータ整形 | `feature/story-parser` |
| エラーハンドリングと再試行 | `feature/llm-error-handling` |

### 🚀 着手の順番（依存関係）
前提となる以下のブランチは並行させず、先に `develop` へマージしてください。
1. `feature/db-schema`: API 系すべての前提。最優先。
2. `feature/llm-client`: AI 連携他 3 本の前提。
3. `feature/list-tabs`: 単語タブ・物語タブの入れ物。

## 📝 3. コミットメッセージ規約

コミットメッセージは以下の種別をプレフィックスとして付けます（内容は日本語でOK）。

| 種別 | 使うとき | 例 |
| :--- | :--- | :--- |
| `add` | 新規ファイル・機能追加 | `add: 単語登録APIを追加` |
| `fix` | バグ修正 | `fix: 空文字が登録できてしまう問題を修正` |
| `update` | 機能修正（バグではない） | `update: 単語の文字数上限を20文字に変更` |
| `remove` | ファイル・機能の削除 | `remove: 使っていないテスト用ページを削除` |

## 🔀 4. プルリクエスト (PR) 規約

- 誰か 1 人にレビューしてもらってからマージします。
- タイトルはコミットメッセージと同じ形式にします。
- レビューは完璧を目指さず、動いていて明らかにおかしくないことを確認する程度で十分です。
- コンフリクトが起きたら 1 人で悩まず、画面共有して一緒に解決しましょう。

### 📋 PR テンプレート

```markdown
## 何をしたか
- 

## 対応カード
- 

## 動作確認
- [ ] ローカルで動作確認した
- [ ] エラーが出ないことを確認した

## チェック
- [ ] コミットメッセージの形式を守っている
- [ ] 不要なコードやコメントアウトを消した
- [ ] console.log を消した
- [ ] 命名規則に従っている

## 補足
<!-- レビューで見てほしい箇所、詰まったところ、相談したいことがあれば -->
```

## 🔤 5. 命名規則

### 🗄️ データベース
- **テーブル名・カラム名**: すべて小文字スネークケース (`user_meaning`, `created_at`)
- **主キー**: `テーブル名_id` (例: `word_id`, `story_id`)
- **日時**: `_at` で終わる (例: `created_at`)
- **真偽値**: `is_` で始める (例: `is_learned`)

### ⚡ JavaScript / TypeScript
- **変数・関数**: キャメルケース (例: `const wordList = [];`, `function createWords() {}`)
- **コンポーネント**: パスカルケース (例: `function WordForm() {}`)
- **全体設定値**: 大文字スネークケース (例: `const MAX_WORD_LENGTH = 20;`)
- **真偽値**: `is` または `has` で始める (例: `const isLoading = true;`, `const hasError = false;`)
- **関数名**: 動詞で始める (例: `getMyWords()`, `createWords()`, `deleteWord()`)
- **イベントハンドラー**: `handle` で始める (例: `handleSubmit()`)
- **配列**: 複数形 (例: `const words = [];`)
- **CSS クラス名・id名**: キャメルケース (例: `styles.storyList`)
- **ファイル名**:
  - コンポーネント: `WordForm.tsx` (パスカルケース・中身と揃える)
  - その他: `create-word.ts` (小文字ケバブケース)

> ⚠️ **DB データに関する重要注意点**:
> Supabase から取得したデータはスネークケースのまま返ってきます。キャメルケースに変換せずそのまま使用してください。  
> ⭕ `data[0].created_at` / ❌ `data[0].createdAt` (`undefined` になります)

## 🤖 6. AI（ChatGPT / Claude / Cursor 等）使用時の指示文プロンプト

AI にコードを書かせる際は、以下の枠内プロンプトを最初に提示して書き方を統一してください。

```text
# プロジェクトの前提
英単語を物語で覚える学習アプリを開発しています。
次のルールに従ってコードを書いてください。

## 技術スタック
- Next.js (App Router) / TypeScript
- Supabase (PostgreSQL / Auth)
- データ取得と更新は Server Actions で行います

## 命名規則
### JavaScript / TypeScript
- 変数・関数: キャメルケース（wordList, createWords）
- コンポーネント: パスカルケース（WordForm）
- 全体で使う設定値: 大文字スネークケース（MAX_WORD_LENGTH）
- 真偽値: is か has で始める（isLoading, hasError）
- 関数: 動詞で始める（getMyWords, createWords, deleteWord）
- イベント処理の関数: handle で始める（handleSubmit）
- 配列: 複数形（words）

### ファイル名
- コンポーネント: WordForm.tsx（先頭大文字、中身の名前と揃える）
- それ以外: create-word.ts（小文字とハイフン）

### データベース
- テーブル名・カラム名: スネークケース（user_meaning, created_at）
- 主キー: テーブル名_id（word_id, story_id）
- 日時: _at で終わる（created_at）
- 真偽値: is_ で始める（is_learned）

### 重要な注意
Supabase から取得したデータはスネークケースのままです。
キャメルケースに変換しないでください。
例: data[0].created_at は正しい / data[0].createdAt は undefined になる

## コードの書き方
- 関数の上に、返り値の形をコメントで書いてください
  例: // 返り値: [{ meaning_id, english, japanese }]
- コメントは日本語で書いてください
- 初心者が読むので、複雑な書き方より読みやすさを優先してください
```
